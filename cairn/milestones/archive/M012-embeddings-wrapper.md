# M012: The package can turn text into embedding vectors

**Status:** done (2026-09-20, PR #13 https://github.com/jmgirard/rlmstudio/pull/13)

**Goal:** Wrap `POST /v1/embeddings` as `lms_embed()`, one embedding row per input text.

**Outcome:** `lms_embed(model, input, host, simplify, ..., token)` in `R/embed.R` sends the
whole input vector as one JSON array and returns an unnamed double matrix, rows placed by each
element's `index` rather than by arrival order. `embed_matrix()` rejects on thirteen conditions
before building, through a new `rlm_abort_bad_response()` in `R/utils-api-error.R`, under the
new condition class `rlmstudio_bad_response` carrying an integer `status`. `json_field()` and
`is_json_object()` read every field by exact name, so `$` partial matching cannot read a
`database` field as the data block. The body parses with `check_type = FALSE`, so a
header-rewriting proxy no longer hides a healthy server; the siblings still reject a non-JSON
content type. `simplify = FALSE` returns the parsed body, unchecked. A live cassette from
`text-embedding-nomic-embed-text-v1.5` at 768 dimensions pins the happy path, generated by
`data-raw/record-embed-cassette.R`.

**Decisions:** D-007.

**Review:** Three passes, full three-lens fan-out each. The first returned on two AC6 failures,
the second on an AC1 failure. The third passed every criterion: of eleven findings, four were
fixed at the gate (a content-type misdiagnosis, a `data` field holding a plain value reported
as absent, a changelog claim, an untested help-page claim) and seven rejected as routed,
deliberate, or refuted. Three amendment returns ran separately. Nothing was retired.
